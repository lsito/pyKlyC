## Working logic

1. Define all raw inputs visibly in the Python notebook, using the MATLAB variable names and units.
2. Calculate using the existing Python classes, inspect the plots, and export raw inputs separately from calculated results.
3. Run the MATLAB Live Script separately. It loads `inputs.mat`, performs the corresponding MATLAB calculations, displays its own plots, and exports `matlab_results.mat`.
4. Run `compare_results.ipynb`. It checks the two result files and reports agreement, errors, and tolerances for each variable.

MATLAB must calculate its own reference quantities and grid. It must not use Python-computed arrays as its starting solution. The comparison notebook compares saved outputs; it does not generate either solution. No MATLAB engine or automatic MATLAB startup is needed.

## Shared data and indexing conventions

`inputs.mat` contains only raw fields from the beam, cavity, tube and numerical parameter objects, plus `factorregion`, `c`, `etom`, and `mu01`. The exported constants record the Python configuration. MATLAB independently defines its constants in the copied solver block: it overwrites the loaded `c` and `etom`, and uses the original literal `2.40483` rather than the loaded `mu01`. The present Python constants match the original MATLAB values; if these ever diverge, investigate that difference rather than forcing the MATLAB test to adopt Python's values. No calculated reference or grid output belongs in this file.

`python_results.mat` contains every field returned by `ReferenceParameters` and `GridParameters`. Both files store top-level named variables, not serialized Python objects.

| Quantity | Python convention | MATLAB convention / export rule |
|---|---|---|
| `Y0` | Zero-based particle indices | `inputs.mat` stores `Y0 + 1` for MATLAB |
| `Nesz[:, 0]` | Zero-based first included node | Add 1 before comparing with MATLAB's first included index |
| `Nesz[:, 1]` | Zero-based exclusive stop | Numerically equal to MATLAB's one-based last included index |
| One-dimensional arrays | Shape `(n,)` | Saved as row vectors `(1, n)` |
| `Nesz`, `rcv`, `kai` | Matrices | Preserve row and column dimensions |

For example, Python's `[0, 53]` means `zi[0:53]`, containing 53 nodes. Its MATLAB equivalent is `[1, 53]`, used as `zi(1:53)`. Native Python bounds remain unchanged in `python_results.mat`; conversion is applied only to a copy in the comparison notebook.

Real integer input parameters are exported as MATLAB doubles to avoid integer-arithmetic surprises. Complex values remain complex. NumPy integer result arrays such as `Nesz` retain their integer dtype.

Use ordinary MAT files compatible with SciPy: Python uses `savemat`, and MATLAB uses `save(..., '-v7')`. Avoid `-v7.3` for this simple `scipy.io.loadmat` workflow.

## Comparison rules

- Require both result files and all expected variables. Missing results mean **not tested**, not passed.
- Check dimensions first. Treat row/column vectors as equivalent only for quantities declared to be vectors; do not flatten matrices to hide shape errors.
- Apply only the documented indexing conversion, without changing physical coordinates or normalization.
- Compare integer counts and index bounds exactly.
- Compare floating-point arrays at every entry using `abs(Python - MATLAB) <= atol + rtol * abs(MATLAB)`, initially `rtol=1e-10` and `atol=1e-12`. The absolute tolerance is in each variable's stored units. Review tolerances by quantity; do not increase them simply to hide a discrepancy.
- Reject unexpected NaN/infinite values and report maximum absolute and relative errors alongside pass/fail. Maximum relative error is calculated only over nonzero MATLAB entries; a dash means none are available. Zero reference entries are still checked using the absolute tolerance.
- Compare every exported reference/grid quantity, not only a plot or final node count.
- Report additional exported variables as NOT TESTED until their comparison rules have been added.

### Controls and disabled-branch diagnostics

- `factor` multiplies `wp`; `Esz00` scales as `factor**2`.
- `factorregion` controls the source-grid extent. Zero produces empty source arrays and a zero field.
- `fillfactor` and `DCSPfactor` are nonzero **gates** in the original prefill block. Their numerical weighting is applied later when combining fields, outside this test. Nonunit positive values therefore do not rescale `Esz00` here.
- Setting `factor`, `fillfactor`, or `DCSPfactor` to zero makes the entire prefill field zero, including RF columns.

Python always retains `zp`, `gamazp` and `QQfill`, even with disabled prefill. Original MATLAB creates them only inside the enabled branch. To keep disabled-case diagnostics available without changing the field calculation, the MATLAB test explicitly repeats the original four source-array lines **only when a gate is zero**. These are test diagnostics, not a claim that the original disabled solver branch returns these arrays. `Esz00` retains its original zero behavior.

### Field reconstruction and its limits

Original MATLAB lines 674, 682 and 692 give

\[
Vng_k=U_0\frac{V_{nc,k}}{\sqrt{k_{0,k}}}\int ez_k(zi)\,d zi
\quad [\mathrm{kV}].
\]

For the same fixed mode shape, this test reconstructs

\[
Ezc_k(zi)=U_0\frac{V_{nc,k}}{\sqrt{k_{0,k}}}ez_k(zi)
\quad [\mathrm{kV/mm}].
\]

Use **k0 in 1/mm**, zi in mm, and ez in mm^(-3/2). One kV/mm equals one MV/m. Integrating Ezc must recover the complex Vng. This is the unweighted gap voltage, not the transit-time-weighted voltage experienced by a moving particle.

The dimensionless field is grouped by harmonic:

\[
Emz_{\mathrm{reconstructed},m}
=\sum_{k:nh_k=m}\frac{Ezc_k}{\beta_e U_0}
=\sum_{k:nh_k=m}C3_kV_{nc,k}\frac{1000U_0}{\eta_0I_0}.
\]

Thus **C3*Vnc alone does not have the operating-field normalization**. Using the solver's imaginary-part convention, field snapshots are

\[
Ezt(zi,\theta)=\beta_e U_0\,\operatorname{Im}
\sum_m Emz_{\mathrm{reconstructed},m}(zi)e^{im\theta}.
\]

Ezc has one column per cavity; Emz_reconstructed has one per harmonic; Ezt has one per snapshot phase. Different harmonics are not combined into one phasor. Vnp represents a port wave, not another longitudinal field to add inside the cavity.

These are explicitly **test-only diagnostic reconstructions inferred from gap-voltage normalization**. The original source inspected here allocates Emz but does not populate it from Vnc. This test neither changes that source nor claims to validate its missing field-update path.

### Power diagnostics and internal checks

Using peak complex amplitudes, power_scale=(1000*U0)^2/(2*eta0):

- Pport = power_scale*abs(Vnp)^2: reflected wave power at an input, outgoing wave power at an output. Bunching ports are placeholders.
- Pwall = power_scale*abs(Vnc)^2/Qin: wall-loss power.
- Pout = (1-abs(gaman)^2)*Pport for output cavities; zero elsewhere.
- power_scale*abs(Vin*drivefactor)^2 = Pin*drivefactor^2.

The field integral gives RtoQ_grid=eta0/k0*abs(integral(ez,dzi))^2, which must satisfy abs(1000*Vng)^2 = 2*Pwall*Qin*RtoQ_grid.

Both languages check the circuit residual, external/beam superposition, voltage doubling when incident power is quadrupled, field/gap consistency, both normalized-field expressions, and these power identities. Without off-diagonal coupling, separate 2x2 solves must match the global solution. An explicit loaded-input-cavity formula additionally checks the externally driven mode voltage.

### Inputs and prescribed beam profiles

The default is a modulated -16 A, 180 kV entrance beam, operating at 1 GHz, on the same 3000 mm domain as the previous tests. The global/local snapshot uses nn=2. \]

### What each method calculates

Both methods use the original five Bessel roots and the same normalized units.

| Output | Local SCmethod=0 | Global SCmethod=1 |
|---|---|---|
| Esz | Computed from local Iz, vez and gamaz | In-domain RF contribution plus weighted upstream prefill |
| Esz0 | Zero | Weighted in-domain and prefill DC contributions |
| Esztotal | Zero placeholder | In-domain source integral, DC first then RF |
| Esz00 | Fixed initializer output; not added locally | Fixed upstream field, included with fillfactor |
| Eszr | Cached geometry factors | Same factors, sampled at source positions |

For each global target node, Nesz selects a finite source window. The integration uses source gamma for RF, gamma=1 for DC, source radius rcvs, the signed exponential kernel, and the physical/normalized spacing conversion. The final combination is

\[
Esz=Esztotal[:,1:]+fillfactor\,Esz00[:,1:],
\]
\[
Esz0=DCSPfactor\,(Esztotal[:,0]+fillfactor\,Esz00[:,0]).
\]

These are Python column conventions. Eszr has five radial-mode columns and units mm^2; it is not an electric field. Fields are dimensionless. Local RF arrays have Ns columns; DC-inclusive arrays have Ns+1.

The local approximation omits DC and prefill. Finite source windows, entrance/exit boundaries, upstream assumptions and varying beam quantities can therefore produce local/global differences. The plots show these differences without treating them as translation failures.

- As in original MATLAB, setting either fillfactor or DCSPfactor to zero at initialization disables the **entire prefill field**, including RF columns. With nonzero values, the prefill calculation itself is unweighted; weights apply during the global update.
